19 of 20 is not a guardrail

Prompt injection is not a bug you fix.
It is a rate you measure.

Every guardrail is a pattern match, so every guardrail has a bypass. The only useful question is what fraction of a documented suite gets through, per layer, per attack category — and whether adding a layer actually moves that number.

Run it against a real endpoint

A target is any HTTP service that takes {"messages":[…]} and returns {"text":"…"}. Point it at a staging model, not production customer traffic.

python -m guardeval run \
  --endpoint http://localhost:8000/chat \
  --layers input.pattern input.structure \
           input.hierarchy output.canary \
  --out out/results.json

  direct override 0/2   0.0
  encoding        2/3   0.667
  tool misuse     2/2   1.0

Those figures are this repo's own run against no target — input layers only. With a live model, output and tool layers join the score.

What the numbers already say

  • Phrase matching is the weakest layer. Blocking "ignore previous instructions" catches the naive cases and almost nothing else — obfuscation, homoglyphs and encodings walk straight past it.
  • Structural checks catch different attacks, not more of the same ones: role-tag injection and JSON role spoofing fail a pattern filter and pass a structure filter.
  • Instruction-hierarchy checks are narrow but cheap — they only help for retrieved content, and they are the difference between an indirect injection being data or an order.
  • Tool guards only work if the tool proxy enforces them. A prompt-level "do not use file://" is a suggestion; the proxy rejecting the argument is a control.

Scope, stated plainly

What this is

A suite of documented, published injection tactics and reference implementations of the guardrail shapes found in production, so the layers can be compared on one axis. Deterministic — same inputs, same score.

What it is not

Not a measurement of any specific model. The page scores layers. Real bypass rates need a live target, per model, per temperature, run more than once — which is what the CLI does.

Why rates

Because a determined user sends 100 prompts. A layer at 95 % is a layer that fails five times a day at that volume, and the operator never sees it unless someone measured the rate first.
